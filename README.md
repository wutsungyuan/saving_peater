## 範例句

「句子」分頁的「句子分析」下方的標籤對應 12 組**內建的教學範例**（五大句型各一、等號測試、
連結動詞接副詞的錯誤、對等連接詞、超出國中範圍的關係子句…），寫死在頁面裡，
點了不呼叫模型也不碰後端 —— 線上展示版就是靠這些。

有後端時，標籤底下會多出「**換成我分析過的句子**」：從 `sentences` 表裡
挑同一類的真實句子，可以一直按換下一句。分類條件寫在 `cache.sampleKinds()`，
直接掃存下來的分析 JSON（上百句的量，比另外建索引實際）：

| 標籤 | 條件 |
|---|---|
| 句型一～五 | 主要子句的 `pattern.id` |
| 主動賓方地時 | 含兩種以上的修飾語（方／地／時／頻）|
| 動詞分段 | 主要子句有兩個 V 成分 |
| 含文法錯誤 | `notes` 裡有 `type: 'error'` |
| 對等連接詞 | 子句數大於一 |
| 超出範圍 | `inScope === false` |

再點一次標籤就回到內建範例。

### 考卷題目

拍考卷時會把**選擇填空題直接還原成完整正確的句子** —— 依 (A)(B)(C)(D) 選出答案填進空格，
選項本身不抄（答案由文法判斷，不看考卷上手寫的答案，那可能是錯的）。
沒有選項但括號裡有提示詞（`Mom _____ (take) …`）就依提示變化填入；
連提示都沒有、答案不只一種時才保留空格。
用真實考卷實測 19 題全部填對，包含學生原本答錯被老師改掉的那幾題。

這樣進資料庫的就是完整正確的句子，之後出題、練習都和一般句子一樣。

### 對話題

`A: … / B: …` 這種題目，**每個人說的話各自成為一句**（說話者標記會拆掉，
不會混進句子裡），但會記下**誰說的**與**對方說了什麼**。
出題時把對方那句顯示在題目上方，所以
`What did you make for your classmates?`（句型三）與
`I made them some cards.`（句型四）的對照不會斷掉。

判斷是不是對話有排除清單：`Note:` `Answer:` `Key:` 這些課本上常見的
「字＋冒號」不會被當成說話者（8/8 邊界測試通過）。

### 填空題

直接貼考卷題目（句子裡有 `_____`）是正常用法，不會被當成錯誤：
`issue` 保持 `null`、空格的內容不列為文法錯誤，而是用 tip 說明
**空格要填什麼詞性、為什麼、可以填哪些字** —— 那正是題目在考的觀念。
介面上標成中性的「填空題」而不是紅色警告。真的另有文法錯誤時才會標出來。

## 換到 Windows

搬機器的完整步驟在 [MIGRATION.md](MIGRATION.md)。下面是為什麼需要那些步驟：

程式本身是跨平台的 Node，但有兩處原本會在 Windows 上直接失敗，已經處理：

- **Claude CLI 的執行檔名**：Windows 裝的是 `claude.cmd`，而 `child_process.spawn`
  不透過 shell 執行不了批次檔。`src/claude-bin.mjs` 依平台選檔名；
  安裝路徑特殊時用環境變數 `CLAUDE_BIN` 指定完整路徑。
  用 `shell: true` 也能繞過，但參數含使用者貼上的文字，等於開了命令注入的洞。
- **Node 版本**：`node:sqlite` 要 22.5 以上（22.14 起免旗標），
  `engines` 原本寫 `>=20` 會讓人裝到跑不起來的版本，已改成 `>=22.14`。

另外加了 `.gitattributes` 把行尾固定成 LF —— `seed-cache.jsonl` 是一行一筆，
行尾被改成 CRLF 的話 git diff 會整檔變動，匯入也可能多出 `\r`。

## 手機

伺服器送出 `prototype/index.html` 時會補上 doctype、charset 與 viewport ——
那份檔案是給 Artifact 用的格式（發布時平台自動包骨架），我們自己送就得補，
否則手機上會是 quirks 模式加 980px 的版面寬度，整頁縮小到看不清楚。
骨架放在 `serveStatic()` 而不是寫進檔案，是為了不破壞 Artifact 的發布規則。

圖例（句子成分、詞性、代名詞格位）在手機上收到左右邊緣，
從邊緣往內滑可以拉出來，邊緣也有把手可以點 ——
純手勢沒有任何提示，第一次用的人不會知道。
抽屜內容直接取自側欄，不另外維護一份。

手機版（≤560px）另外做了：分頁改為可橫向捲且字不折行、開頭說明收成兩行可展開、
句子與標註字級縮小、按鈕與選項高度拉到 40px 以上、輸入框字級固定 16px
（iOS 低於 16px 會自動放大整頁）、出題後自動捲到第一題。

用無頭 Chrome 量過 360／390／430px 五個分頁都沒有橫向溢出，
768／1180／1400px 的桌機版面不受影響。

# 英文句型解剖

貼上一句話或一段英文文章，逐句分析**句型、詞性、時態、文法問題**，並給繁體中文翻譯。
文法規則取自 `國中英文文法_句型與時態.md`（五大基本句型 ＋ 16 種時態）。

## 快速開始

```bash
npm start          # http://127.0.0.1:8787
```

零依賴 —— 只用 Node 22 內建的 `node:http` 與 `node:sqlite`。
分析透過 Claude Code headless（`claude -p`）呼叫，使用你現有的 Claude 訂閱認證，不需要 API key。

## 學生與老師：前台與後台

同一個伺服器、同一個資料庫，兩個入口：

| | 前台 `/`（學生練習用，老師也能進） | 後台 `/admin`（只有老師） |
|---|---|---|
| 分頁 | 單字、句子、文章、測驗卷、弱點（學生另有「我的申請」） | 待審、測驗卷、單字表、文章表、句子、學生紀錄、費用與用量 |
| 單字 | 清單與**搜尋**（中英文，跨全部字表）、單字測驗 | 新增字表、刪除、批次分析例句 |
| 句子 | 句子分析（只分析、不存）、句子練習 | **句子管理**：搜尋、看分析、排除出題、重新分析、刪除 |
| 文章 | 文章表、新增文章 | 看與刪除文章表 |
| 測驗卷 | 只看與作答老師**已發佈**的卷子 | 出卷、草稿編修（換題、刪題）、發佈與收回、看學生逐題的作答 |
| 弱點 | 自己的紀錄：單字測驗、句子練習、測驗卷綜合 | 「學生紀錄」：同一份資料，加上**整理（刪除）紀錄** |

學生打 `/admin` 回 403「這個頁面只有老師能用」。老師從 `/` 右上角的「進入後台」進去，**不會自動導過去**（老師想試用學生畫面時不會被帶走）；老師自己在前台試用的作答記在 `teacher`，不混進學生的紀錄。

### 帳號

- 老師：`AUTH_USER` / `AUTH_PASS`（和以前一樣）。
- 學生：`STUDENT_USER` / `STUDENT_PASS`（選填，不能和老師同名）。
- **沒設學生帳號就和以前完全一樣**：只有一組帳密，等於老師；舊的 `AUTH_TOKEN` 也等於老師。
- 兩組帳密都放在專案外的 `start.ps1` 之類的地方，不進程式碼與 git。session 記著角色（`sessions.role`）。

### 花費關卡（學生要花額度的操作要老師核准）

學生按了會呼叫模型的操作，不直接執行，改開一張**申請單**；老師在後台「待審」核准後，伺服器才在背景執行（一次一張）。

| 學生做的事 | 行為 |
|---|---|
| 分析句子 | 已分析過的（快取命中）馬上出，**沒分析過的**標「等老師核准」並開申請單；同樣內容重複送出沿用同一張 |
| 分析並存成文章 | 確認框只有句數，按「送出申請」；核准後自動分析並存成文章 |
| 拍照辨識（句子、單字表） | **每天免審直接辨識**（`STUDENT_OCR_PER_DAY`，預設 10 張，句子與單字表合計；0＝一律申請）；超過才開申請單。辨識完後面的分析、建字表仍要核准 |
| 申請新增單字表、AI 批改 | 申請單，核准後才做 |

- 背景執行是用**老師身分把同一個請求重送給現有的流程**（`src/internal.mjs`），結果和老師自己按完全一樣；失敗的申請單可以「重新執行」，分析有快取所以只處理失敗的句子。
- 學生看不到任何費用；老師在「待審」看得到每張的句數、**預估費用區間**與時間，處理過的顯示實際花費。
- 伺服器重啟時沒做完的申請單會接著做；結束超過 60 天的自動清掉。

### 學習紀錄固定記在身分下

作答紀錄由**伺服器**決定記在誰名下，不再看瀏覽器自己產生的隨機代碼：學生記在 `student`，手機、筆電、換瀏覽器都是同一份（有設學生帳號時老師記在 `teacher`；沒設時唯一的使用者就是 `student`）。

升級前就存在的舊隨機代碼用命令列合併：

```
node src/cache-cli.mjs users                              # 列出每個代碼的作答數與時間
node src/cache-cli.mjs merge-users student <代碼1> <代碼2> …   # 合併，先自動備份
```

單字熟練度同一個字有好幾筆時，盒子與到期日取練得最多的那筆、答對與作答次數相加。

### 後台管理的細節

- **句子管理**：列出所有已分析的句子，搜尋原文或翻譯，篩選（有問題、已排除、超出範圍、沒被文章用到）。**排除出題**＝畫面照常顯示，但練習與測驗卷不再用它出題（`sentences.excluded`）；**重新分析**先報價、確認才呼叫，失敗會把舊結果放回去；被文章表用到的句子不能刪。
- **測驗卷**：出卷後是**草稿**，學生看不到。可以改名、**換一題**（同範圍同題型、不花額度）、**刪一題**（分數重新分配，滿分維持 100，至少留 10 題）；閱讀、克漏字、文意選填跟文章綁在一起不能單題編修，模型出的延伸題只能刪。滿意了「發佈給學生」；已發佈但學生還沒開始作答可以「收回」。
- **整理學生紀錄**：依類別（句子練習、單字測驗、測驗卷）、日期、單字表、是否連熟練度一起清；先**預覽會刪多少**，條件改了要重新預覽，確定要按兩次；刪之前自動備份整個資料庫（`backups/`，留最近 10 份），並寫進操作紀錄（`audit_log`）。只動學生的紀錄。

### 升級到這一版

資料庫會自動升級（第 5～10 版：作答來源、session 角色、申請單、請求紀錄的角色、句子排除、操作紀錄），升級前自動備份到 `data/backups/`。學生帳號與免審辨識張數都是選填。上線前建議先看 `users` 清單，決定哪些舊代碼要併進 `student`。

## 它會分析什麼

| 層次 | 內容 |
| --- | --- |
| 句型 | 五大基本句型（S+V ／ S+V+C ／ S+V+O ／ S+V+IO+DO ／ S+V+O+C），逐成分標出 S/V/O/C/IO/DO 與修飾語 |
| 詞性 | 12 種（n, pron, v, aux, adj, adv, prep, conj, art, num, to, interj），形容詞與副詞特別標色 |
| 代名詞格位 | 主格／受格／所有格／所有格代名詞／反身，`her`、`his` 這類一字多格也能分辨 |
| 時態 | 4 時間 × 4 狀態共 16 格，標示是否屬於國中範圍的 7 種 |
| 動詞 | 三態（原形／過去式／過去分詞）＋ -ing ＋ 三單，不規則動詞標 `v°` |
| 文法 | 12 類常見錯誤偵測（連結動詞接副詞、第三人稱單數、完成式配過去時間、to/for、受格…） |
| 語序 | 「主、動、賓、方、地、時」六格拆解 |
| 翻譯 | 繁體中文（台灣用語） |

### 國中範圍的判定

範圍是依**課綱**而非講義的涵蓋範圍 —— 講義只教五大句型與時態，
但被動語態、比較級、關係子句這些國中也要學。

**算在範圍內**：疑問句（Yes/No、Wh-、附加問句）、間接問句、否定句、被動語態、
比較級與最高級、祈使句、There be、使役與感官動詞、不定詞與動名詞、
關係子句的基礎用法（who / which / that）、so…that、too…to，
以及 7 種時態（必學 6 種＋過去完成式）。

**標為超出範圍**：分詞構句、假設語氣、完成進行式、未來進行式與未來完成式、
過去未來式、關係子句的進階用法（whose、介系詞 + 關代、非限定）、
that 引導的名詞子句、倒裝句。超綱時仍會照實分析主幹，只是多一個標示與說明。

被動語態的句型依**轉換後剩什麼**決定：主動句型三 → 被動句型一、
主動句型四 → 被動句型三、主動句型五 → 被動句型二，並附主動語態的改寫。
非英文、不完整片語、無意義字串會標 `issue` 並明說無法分析，不會硬掰。

## 單字表

字表有三種建立方式：**貼上文字**（一行一個，可用逗號接中文）、
**拍照／選檔**，或把圖片**直接拖進來／按 ⌘V 貼上** ——
從 LINE、相簿、Finder 拖過來都可以，整個「單字」分頁都是放置區，
表單沒開會自動打開。

「句子」分頁也能拍照：把課本、講義或考卷上的**英文句子**抄下來填進輸入框，
之後完全走原本的流程（斷句 → 逐句分析 → 快取），和自己貼上一整段沒有差別。
用的是另一份辨識規格（`prompts/analyze-ocr.md`）—— 這邊要的是完整句子與段落，
會略過中文翻譯、音標、題號與手寫筆記，跨行的句子會接回同一句。
輸入框裡如果是範例句就直接覆蓋，自己打的內容才接在後面。

拍照辨識會把課本單字表抄成文字填進輸入框，**讓你核對後再建立** ——
辨識可能有誤，不直接拿去花額度充實。實測一張課本頁 10 秒抄出 25 個字，
而且會自動忽略手寫筆記、音標、詞性方格與發音要點。
照片上傳前先在瀏覽器縮到最長邊 1600px，手機原圖約縮到十分之一。
照片只在辨識當下寫成暫存檔，用完立刻刪除，不留在硬碟上。

新增表單最上方是一個**可輸入的下拉選單**：打新名字就是建新字表，
從清單選既有的就是加進那一份（家教每次加幾個字到同一單元，不用每次開新的）。
底下即時顯示會發生什麼，送出鍵的文字也跟著變。

新增狀態下只做一件事，所以字表卡、多選、刪除全部收起來，
「＋ 新增字表」也變成「← 回到單字表」。加入時那份已經有的字
會先濾掉，既不會重複也不會重複花額度 —— 全部都重複時連模型都不呼叫。

單份字表裡的字是唯一的，但同一個字可能出現在多份字表（例如整頁的字表
包含了小範圍那份）。多選時會**合併成一張卡**：詞義與例句取聯集，
所以兩份字表各給的例句都看得到，卡片上標示「合併 N 份」。

作答會**同步寫到所有重複的那幾列**，所以之後單看任何一份字表，
那個字的熟練度都是對的。合併顯示時取練得最多的那一筆而不是相加 ——
相加的話同一次作答會被算兩次。實測多選出 6 題就是記 6 次。

字表**直接點就是加選或取消**，單字清單、測驗與批次分析都會把選取的合在一起
（至少要留一份）。不另外做「多選模式」—— 多一個開關只是多一層操作，
而刪除本來就有兩段確認擋著。
刪除會連同那些字表的**所有作答與熟練度一起消失**（句子分析快取不受影響，
那是以句子為單位、和字表無關），所以要按兩次確認。

字表名稱不預填 —— 使用者本來就會自己取（Unit1、Unit2…），
預填只是多一步刪除；真的沒填才用「單字」當後備。
名稱裡也不用寫日期，字表上本來就獨立顯示建立日期。

批次分析用串流回報進度：每 8 句一批，**跑完一批就寫進快取**，
畫面上顯示「分析中…16 / 41 句（$0.70）」。幾十句要跑好幾分鐘，
全部跑完才一次交付的話，中途斷線會全部白做，畫面也完全沒有動靜。
現在斷線最多只損失一批，再按一次會從沒分析的接著跑 ——
模型呼叫次數完全沒變（41 句一樣是 6 次），失敗時反而省。

每個例句後面有「分析」，點了跳到句型分析。按鈕會分成兩種狀態：
**虛線框**＝還沒分析（點了會花一次額度）、**實線框加勾**＝已分析過
（點了瞬間出結果，不花額度）。不只靠顏色區分，色盲或黑白列印也看得出差別。
分析完回到清單會立刻更新。字表上方的「批次分析例句」
會把所有例句一次分析完，之後點任何一句都是瞬間且不花額度的。

### 為什麼批次比較省

每次呼叫模型都要重讀約 34K tokens 的系統提示，逐句送就是付 N 次。實測六句：

| | 呼叫次數 | 費用 | 輸出 tokens | 時間 |
|---|---|---|---|---|
| 逐句 | 6 | $0.164 | 6,125 | 72s |
| 整批 | 1 | $0.099 | 4,592 | 37s |

省 40% 費用、49% 時間，而句型、時態、詞性對齊與原句都與逐句分析完全一致。
`analyzeMany()` 每 8 句併一次呼叫，回來後用 `original` 逐一對回去，
模型漏句或併句時那幾句自動單獨重送 —— 寧可多花也不能給錯的結果。

例句分析完會併入練習題庫（一份字表約多 26 句），出題不另外花錢。

兩個輸入框（分析、新增字表）在呼叫模型時都會蓋一個轉圈指示並跳秒數 ——
整理一份字表要將近一分鐘，沒有東西在動會讓人以為當掉了。

「單字」分頁底下分成「單字清單」與「單字測驗」兩個子頁，
**預設停在單字清單** —— 平常是背單字、看例句，要考試才切過去。

「單字」分頁貼上老師給的考試範圍（一行一個，可用逗號接中文），系統會整理出
**每個詞性的意思、例句、音節拆解、拼字提醒、易混淆字與衍生字**，然後循環測驗。

建立時每批單字呼叫一次模型（15 個字約一分鐘），**之後所有測驗都由程式生成，不再花額度**。

### 五種測驗模式

| 模式 | 形式 |
| --- | --- |
| 中考英 | 看中文寫英文，提示給音節骨架 `__-___-__-___` |
| 英考中 | 看英文選中文，誘答從同字表其他字取 |
| 聽考 | 用朗讀唸出單字，聽完拼出來（配合自然拼音） |
| 例句填空 | 例句挖空填入，變化形（finishes）與原形都接受 |
| 詞義辨析 | 同一個字在不同句子裡是不同意思，選出這句是哪個 |

最後一種是為「一詞多義」設計的。實測 15 個字裡有 9 個是多詞性，
例如 `free` 有免費的／自由的／有空的三個意思、`own` 有形容詞「自己的」與動詞「擁有」，
每個意思都配一個能看出語境的例句。

題型用輪流取的方式，五種各佔 20%。

### 間隔複習（Leitner）

每個字有一個「盒子」：答對往上一盒、答錯打回第一盒。盒子越高，下次出現的間隔越長
（10 分鐘 → 1 小時 → 1 天 → 3 天 → 7 天 → 14 天）。出題時到期的字優先，
沒考過的次之，已經熟的最後。這樣循環練下去，弱的字自然會一直回來。

單字清單裡每個單字與每個例句旁邊都有朗讀鈕，再按一次停止。

### 不輸出音標

孩子學的是自然拼音，所以提供**音節拆解**（`un-der-wa-ter`）與**拼字提醒**
（lesson 中間兩個 s、design 的 g 不發音），不輸出 KK 音標。發音靠朗讀功能直接聽。

## 練習模式

「句子」分頁的「句子練習」子頁，從**分析過的句子**反向生成題目（被老師標成「排除出題」的不會用）。
句子本身已經有空格（考卷填空題）時，不會再被拿來出挖空類的題目 ——
畫面上會出現兩個空格卻只收一個答案，看不出要填哪一個。

時態填空會補上三個線索，避免猜不到答案：空格吃掉助動詞或否定時標明共幾個字
（`I ___ coffee.（like，共 3 個字）`）、句子裡看不到時態線索時直接在題目講明時態、
以及一律附上中文翻譯（否定與語氣都看得出來）。

六種題型（中考英、英考中、聽考、例句填空、詞義辨析、**動詞三態**）。
動詞三態是單字層級的知識，放在有間隔複習的單字測驗才有用，
所以從句子練習移過來了 —— 句子練習專注在句型、時態、詞性、改錯、代名詞。
三態資料直接取自分析過的句子（目前涵蓋 59 個動詞），不另外花額度；
兩種寫法（`got / gotten`）都算對，解釋會寫明。

五種題型：

| 題型 | 形式 | 範例 |
| --- | --- | --- |
| 句型判斷 | 五選一 | `Last week our teacher gave us a difficult test.` → 句型四 |
| 時態填空 | 填空（給原形） | `The news ______ his parents proud.`（make）→ made |
| 詞性判斷 | 四選一 | 「confident」在這句是什麼詞性？→ adj |
| 動詞三態 | 兩格填空 | `give → ______ → ______` → gave, given |
| 改錯 | 填空 | `The soup tastes well.` → tastes good |
| 代名詞格位 | 五選一 | 「mine」在這句是哪一種格位？→ 所有格代名詞 |
| 代名詞填空 | 填空（給主格） | `She is ______ teacher.`（I）→ my |

代名詞填空只出「提示的主格 ≠ 答案」的題目 —— (I) → I 等於直接給答案，沒有練習價值。

**出題不呼叫模型。** 分析結果裡已有句型、成分、時態關鍵字、詞性、三態與錯誤修正，
由程式反向生成，所以零成本、1 毫秒完成，而且題目與解答必然和分析一致。

解答沿用講義的解說語言（等號測試、關鍵字 → 時態、三態表）。
答案不隨題目下發，交卷時才由後端批改並記錄，批改時大小寫、空白、句尾標點都不計較。

## 朗讀

每句卡片右上角有朗讀按鈕，點下去唸該句，**唸到哪個字那個字就亮起來** ——
底下的句型色線與詞性標示仍然看得見，聽到 `made` 的同時看得到它被標成 `v°`。
工具列可選語音與速度（慢 0.6／適中 0.85／正常 1.0），設定存在 localStorage。

**完全不消耗任何 API 額度**，也不需要網路 —— 用的是瀏覽器內建的 Web Speech API。

### 發聲層是可抽換模組

`prototype/speech.js` 是獨立的一支，介面固定：

```js
Speech.ready()                  // 等語音清單載入（Chrome 是非同步的）
Speech.available()              // 這個瀏覽器能不能發聲
Speech.voices()                 // [{ id, name, lang, local, wordEvents }]
Speech.settings / setSettings({ voiceId, rate })
Speech.speak(text, { onWord, onStart, onEnd, onError })
Speech.stop() / Speech.speaking()
```

### 代名詞格位是程式決定的

`mine / yours / hers / my / me / I` 這些形式只有一種可能，所以**由程式直接判定**，
不交給模型碰運氣（實測模型偶爾會漏填）。只有 `her`（受格或所有格）、
`his`（所有格或所有格代名詞）、`its`、`it`、`you` 真有歧義時才採用模型的判斷，
模型沒填時再用「後面有沒有接名詞」的規則補上。

這個校正在**讀取快取時也會執行**，所以規則更新後舊的分析結果不必重跑就會補上格位。

`onWord({ start, end })` 的字元座標與分析結果的 `words[].start/end` 同一套，
所以逐字標示不需要額外對齊。之後要換成 Kokoro-82M 等本機神經網路 TTS，
只要替換這一支並維持同樣介面，呼叫端完全不用動。

### 跨平台的語音選擇

不寫死語音名稱（`Samantha` 在 Windows 不存在）。選擇順序：

1. **只挑本機語音** —— 實測雲端語音（Google US English）**完全不發逐字事件**，
   選到就會失去逐字標示
2. 依偏好清單：macOS 的 Samantha / Alex / Daniel…、Windows 的 Microsoft Zira / David / Mark…
3. 過濾掉 macOS 的趣味語音（Bells、Boing、Zarvox…）
4. 都沒有就取第一個英語本機語音

選單裡不支援逐字的語音會標示「（無逐字標示）」。

## 弱點統計

「弱點」分頁統計各維度的正確率，依**五大句型、必學 6 時態、詞性、題型**四組呈現：

- 橫向長條依正確率著色（紅＝最弱、琥珀＝待加強、綠＝熟練），
  百分比、分數與狀態文字一律並列，**不靠顏色辨識**
- 作答數少於 2 的維度標為「資料不足」，不下判斷
- 沒作答過的句型與時態仍然列出並標「無資料」，才看得出哪些還沒練到
- 超出國中範圍的時態（現在完成進行式等）另外列在時態區下方

色票經 `dataviz` 技能的 `validate_palette.js` 驗證：
紅 `#a82a1e` / 琥珀 `#b8821f` / 綠 `#0f6637`，
色盲下相鄰 ΔE 15.1、正常視覺 20.1、對比皆 ≥3:1，全數通過。

### 弱點驅動出題

出題時依這些正確率加權，權重 `0.25 + (1 − 正確率) × 2.25` ——
全錯的維度約 2.5 倍、全對的約 0.25 倍、沒作答過的為中性 1 倍。

實測 200 輪、每輪 10 題的分佈變化：

| 維度 | 正確率 | 關閉加權 | 開啟加權 |
| --- | --- | --- | --- |
| 句型四 | 0% | 13.5% | **25.8%** |
| 句型一 | 25% | 20.0% | **34.5%** |
| 句型三 | 83% | 41.8% | 22.3% |
| 過去簡單式 | 20% | 52.8% | **65.5%** |
| 現在簡單式 | 80% | 38.5% | 24.0% |

紀錄記在固定的身分下（見上面「學習紀錄固定記在身分下」），換裝置、換瀏覽器都是同一份。「弱點」頁可以切換來源：全部、單字測驗、句子練習、測驗卷（含單字面向與近期成績）。

## 文章表

文章在「文章」分頁：**文章表**與**新增文章**兩個子頁（句子分析在「句子」分頁，只分析、不存）。像單字表一樣，一份文章可以一直附加，
也可以一次選多張照片（每張辨識完依序接在輸入框後面）。

「新增文章」的輸入框下面有「**文章名稱**」（要填）：

- 留空 → 照原本的即時分析，不存。
- 打新名字 → 分析完成後存成一份新的文章表；打已經有的名字（下拉可選）→ **接在那份後面**，重複的句子自動略過。

流程：按「分析並存成文章表」→ 先**報價**（`dryRun`，不呼叫模型：幾句要分析、幾句已快取、預估花費與時間）→
你按「確定，開始分析」才呼叫模型 → 全部分析完才存檔（有失敗或中斷就不存，已分析的句子都在快取裡，再按一次只處理缺的）。

**分析是批次的**：沒有快取的句子每 6 句併成一次呼叫（`ANALYZE_GROUP`，設 1 就是逐句），
每次呼叫都要重讀約 34K tokens 的系統提示，併起來就只付一次。模型回來的句子要和我們送的原句逐一對得上，
對不上的那句退回單句再送；整批失敗也是退回單句；額度用盡就立刻停。
實測六句整批約 US$0.17（每句 $0.028），逐句約 $0.13。

**分析中不要離開**：輸入框會蓋上「文章分析中，請不要離開這個畫面」，電腦版關分頁會先警告。
中途離開時瀏覽器記下「這篇還沒完成」（`localStorage`），下次進分析頁出現
「上次『…』的分析沒有完成，按此繼續」—— 繼續會先給報價，只處理剩下的。

**文章表只存順序**：段落 → 句子的 hash。分析結果在 `sentences` 快取（以單句為單位），
所以文章表、單字、句子練習、測驗卷共用同一份分析，不重複花錢。`prune` 不會清掉文章表用到的句子。

**斷句和對話**：文章用和即時分析**完全相同**的斷句（換行也是句子邊界），否則文章表的句子在快取裡對不上。
斷句表裡 `No.` `Sat.` `Sun.` `Mon.` `Wed.` `Fri.` 同時是常用字，只有後面接數字（`No. 5`）才當縮寫；
`No. I can't…` 要在 `No.` 後面切開（以前當縮寫，兩句黏成一句、後面那句丟掉）。

對話課文（每行 `Jamie: …`、至少兩個說話者）：說話者標記不進句子，**一個人說的話再拆成一句一句各自分析**
（模型只會回第一句的話會丟內容，所以一定要一句一句送），但記下是誰說的、屬於第幾次發言。
畫面上同一個人說的幾句**框成一組**：上面是說話者、整段原文與整段翻譯，下面才是每句的分析卡。
文章表的「段」就是一次發言，標題是說話者名字。
模型若把我們送的一句拆成好幾句（斷句和模型意見不同），標成「分析失敗」並說明，不悄悄只留第一句。

分析提示詞另外規定：對話裡的口語應答（`Great.` `Right.`）、省略句、直述疑問（`You have a snowboard?`）、
單獨的語氣詞（`Wow!`）**不算文法錯誤**，先還原完整說法再判斷句型，用一則 tip 說明。

模型偶爾不照格式回（回一句不相干的話、或 `original` 是空的）。第一次不行就**同一句自動再問一次**，
重試時把句子包進一行明確的指令（`Analyze this sentence and reply with JSON only: …`），兩次花費都計入。

照片辨識的課本對話課文會**保留人名說話者標記**（`Jamie: …`，每次發言一行），這樣貼進分析才認得是對話；
考卷題目裡的 `A:` `B:` 仍然去掉。

檢視文章表：每句顯示原文與翻譯，可「展開分析」（完整的句型圖，含詳解與朗讀）；選一份單字表就**標出文章用到了單字表的哪些字**
並顯示涵蓋數；可改名、刪除（兩段確認，不刪分析快取）。

## 測驗卷

「測驗卷」模擬國中紙本試卷（不含聽力）。老師在後台出卷與發佈，學生在前台作答。流程：

**範圍（單字表、文章表各自勾選）→ 題數（25–50）→ 難度 → 題型 → 預覽配題與報價 → 出卷 → 作答（自動存檔，可續做）→ 交卷 → 錯題在前 → 自評或請 AI 批改 → 訂正 → 歷史**

### 題型

| 題型 | 怎麼出 | 模型 |
| --- | --- | --- |
| 單題選擇 | 單字題（意思、詞性）＋文法題（時態、代名詞格位、動詞形式），從分析結果反向生成 | 不用 |
| 閱讀測驗 | 文章（最多 300 字，每句編號）→ 模型出 4 選 1，附依據句編號 | 要，一篇文章一次 |
| 克漏字 | 文法型（介系詞、連接詞、代名詞、動詞形式）由程式挖；語意型的干擾項請模型寫 | 干擾項要 |
| 文意選填 | 從文章挖出字表裡的字，字庫是答案加 2 個多餘的字 | 不用 |
| 情境應答 | 對話課文：上一個人問、下一個人答，選出最適當的回應 | 干擾項要 |
| 句子重組 | 單句（4–14 字、單一子句）拆成成分積木 | 不用 |
| 改錯 | 真實錯誤（分析的 error note），或保證會錯的改法（第三人稱單數、有過去時間線索的過去式） | 不用 |
| 單字填空、配合題 | 字表的字 | 不用 |
| 翻譯、造句 | 開放題，批改預設是程式檢查加自評 | 不用（可選 AI 批改）|

每題分數 = 100 × 權重 ÷ Σ(題數×權重)，**在題數範圍內挑「剛好加總 100 分」的配題**（進位到 0.5，尾差由前幾題各加減 0.5）。
自動配題：核心三塊（單題選擇、閱讀、克漏字，沒有文章表就只有單題選擇）一定出現，再隨機補；25–34 題抽 3–4 種、35–50 題抽 4–5 種。
自選題型：勾哪些出哪些，湊不滿題數時放寬範圍。種子相同配題與題目就相同（預覽和正式出卷是同一份）。

### 難度

難度 = **題目有多少比例是「延伸題」（和範圍有關、但不在範圍裡的）**，以題數計：簡單 0、中等 30%、困難 60%。
延伸題**先用免費的**：字族、易混淆字（字表充實時已經存好，附詞性與中文）當單字題的**答案**；
當選擇題的干擾項不算延伸。免費的不夠才請模型用範圍內的字寫新題目（選擇、重組、改錯、翻譯、短文），
而且要通過檢查：用到範圍內的單字、新字不超過上限。

### 成本控制（核心原則：花錢前先報價、你確認才花）

1. **能用程式出的就不問模型**；模型題先看**題庫**（`questions` 表）有沒有現成的，用過次數少的優先。
2. 缺的題彙整成**最少次數的呼叫**：每篇文章一次（閱讀題＋語意干擾項）、延伸題全部合成一次、情境應答每篇對話一次。
3. **預覽就列出報價**（不呼叫模型）：幾次呼叫、約幾題、US$ 區間（上限含第一次呼叫的暖機成本）、預估秒數；
   有紀錄後改用實際單價（`kind='paper-gen'`）。出卷按鈕上寫明費用，沒確認直接出卷會回 `409 confirm-required`。
4. 每次呼叫帶 `--max-budget-usd` 硬上限；額度用盡或認證失效就停，已出的卷子照樣能用，只是沒有模型題。
5. 模型寫的內容先過程式檢查（`validate.mjs`：選項剛好 4 個且不重複、答案索引、依據句存在、新字不多、干擾項長度與格式），
   不合格的丟掉，**只補缺的那幾題**（一次重試，不整批重來）。解析 JSON 失敗也會重試一次。
6. 通過檢查的存進題庫，之後的卷子優先重用，**第二份起通常不花錢**。
7. **省錢模式**：完全不呼叫模型，只用程式出題與題庫現成的題。

出題模型用 `EXAM_MODEL`（預設 `sonnet`，比分析用的 opus 便宜）。實測（你的 Unit1＋兩份課文、困難 40 題）：
出卷約 US$0.24、補缺的延伸題約 $0.07，57 秒＋17 秒；報價是保守估計。

### 對話課文

閱讀測驗、克漏字、文意選填的文章，對話課文每次發言一行、前面標說話者（`Jamie: …`），模型也看得到說話者。
新題型**情境應答**：題目是上一個人問的話，選項是下一個人的回應。**正確答案就是課文裡真正的回答**（程式找配對，不花錢），
只有 3 個干擾回應才請模型寫。配對規則：上一次發言以問句結尾、換人說話、回答 3–25 字、回答的第一句不是問題。
提示詞規定干擾回應要「答非所問、人稱或時態對不上、或和情境矛盾」，不能把「另一種合理的答法」（接受 vs 拒絕）當干擾項 ——
這點程式只能靠提示詞約束，出給小孩前快速看一眼選項比較保險。

### 批改、自評與 AI 批改

選擇、填空、改錯、重組由程式批改。造句和翻譯是開放題：程式先做能做的檢查（有沒有用到指定的字、大小寫、標點、主要的字出現了幾個），
**其餘由學生或家長自評**（標「我答對了／沒答對」，分數更新）。自評不計入弱點統計。

想要更準確可以按結果頁的「**請 AI 批改**」（選用）：先顯示報價，確認後**一次呼叫**批改全部有作答的造句與翻譯
（`prompts/exam-grade.md`，國中標準、從寬但文法要對，同義說法不扣分），每題給對／錯、一句評語、錯的附建議寫法，
結果寫進自評欄位（學生仍可覆蓋）。沒作答的題不批改；批改過的不重複批改；額度用盡就說明並維持自評。
實測 10 題約 US$0.05–0.15。

### 訂正、統計與歷史

交卷後答錯的題排最前面。「訂正錯題」把答錯的題重出一次（選項順序重排），**不列入統計、不改變原卷分數**。
統計只認**第一次作答**：選擇、填空、改錯、重組記入弱點統計（`paper-*` 題型）；自評與 AI 批改的題不計。
卷子存在 `papers` 表（快取性質）：預設保留 30 天、最近 20 份（`PAPER_DAYS`、`PAPER_KEEP`），到期自動清掉。
題庫不隨歷史清除，只設上限（`QUESTION_MAX`，預設 500，用過次數多的先清）。可以列印題目卷或答案卷。

程式在 `src/papers/`：`plan.mjs`（配題與計分，純函式）、`pool.mjs`（素材池）、`gen.mjs`（程式出題器）、
`model.mjs`（模型出題、報價、題庫）、`validate.mjs`（入庫前檢查）、`grade.mjs`（批改）、`aigrade.mjs`（AI 批改）、`paper.mjs`（卷子生命週期）。
提示詞在 `prompts/exam-gen.md` 與 `prompts/exam-grade.md`。

## 登入

伺服器對外開放時需要驗證。有兩種方式（可同時設定）：

- **帳號密碼**（建議）：環境變數 `AUTH_USER`、`AUTH_PASS`（老師）與選填的 `STUDENT_USER`、`STUDENT_PASS`（學生），**各只有一組，沒有帳號管理**。登入成功發一個隨機的 session 碼，
  放在 `HttpOnly`、`SameSite=Lax` 的 cookie（預設 90 天，`SESSION_DAYS`）；資料庫（`sessions` 表）只存碼的 SHA-256，不存原碼。
  網頁沒登入時最上面會出現登入框，登入後所有頁面的請求自動通過；右上角有「登出」。
  同一個來源連續輸錯 5 次鎖 5 分鐘（鎖住期間連正確密碼也不行）。帳密比對是常數時間。
- **存取碼**：`AUTH_TOKEN`，用 `x-auth-token` 標頭或 `?token=`，給腳本與測試用，網頁不需要。

帳密請放在**專案外面**（例如 Windows 的 `start.ps1`），並且寫在啟動 `node` 那一行**之前** —— 寫在後面不會生效。
換密碼：改檔案、重啟服務。已登入的瀏覽器的 session 存在資料庫裡，**重啟後仍然有效**直到 90 天到期；要全部踢掉就清空 `sessions` 表。

公開的只有 `/api/health`（頁面一開就要用，回報模型、上限與是否需要登入）、`/api/samples`、`/api/login`、`/api/logout`。
其餘（含歷史、統計、弱點、單字表）都要驗證。

## 開發與測試

**開發用分支，不要在跑著正式服務的資料夾切分支** —— 那個服務就是從這個資料夾讀程式的，
檔案一換，正在用的人立刻跟著變。用 `git worktree` 把開發分支放在另一個資料夾：

```bash
git worktree add -b dev ../saving_peater-dev main      # 只需要做一次
cd ../saving_peater-dev
# 資料庫複本（用 VACUUM INTO 取得一致的複本；data/ 不進版控）
node --no-warnings -e "const {DatabaseSync}=require('node:sqlite');require('fs').mkdirSync('data',{recursive:true});new DatabaseSync('../saving_peater/data/cache.db',{readOnly:true}).exec(\"VACUUM INTO 'data/cache.db'\")"
PORT=8788 node --no-warnings src/server.mjs             # 開發版用 8788，正式服務用 8787
```

| 指令 | 內容 |
| --- | --- |
| `npm test` | 遷移、字數提示、JSON 解析、斷句、配題計分、出題器；API 基準（含每條路由要驗證）、假 CLI 路由（批次、重試、額度用盡）、文章表、測驗卷（程式出題、模型出題、對話）、登入。全部不呼叫模型、不花額度 |
| `node --no-warnings test/browser/articles-ui.mjs`、`papers-ui.mjs` | 文章表與測驗卷的畫面流程（真的 Chrome，自己開接假 CLI 的伺服器，**不需要先開伺服器**；含登入框、報價確認、AI 批改） |
| `BASE=http://127.0.0.1:8788/ node --no-warnings test/browser/run-all.mjs` | 瀏覽器測試（真的 Chrome，連本機資料庫，所以只測開發版） |

- **假的 Claude CLI**：`test/fake-claude.mjs`。測試時設 `CLAUDE_BIN=<node>` 與
  `CLAUDE_ARGS_PREFIX='["test/fake-claude.mjs"]'`，分析、拍照辨識、建字表都能完整跑過，不花任何額度；
  可注入額度用盡、單句失敗。`test/api/model-routes.mjs` 就是這樣用的。
- **資料庫遷移**：新增表或欄位時，在 `src/migrations.mjs` 加新的一版（版本號連續遞增），
  不要改已經發布的版本。啟動時自動套用，升級前自動備份到 `data/backups/`（只留最近 5 份）；
  資料庫版本比程式新時會拒絕啟動，避免舊程式弄壞新結構。
- **`DB_FILE`** 環境變數可指定資料庫位置（測試與開發用）。
- 目前已知失敗的瀏覽器測試：`mobile-audit`（按鈕高度與縮排稽核）；`reorder2` 需要資料庫裡有答錯紀錄；
  舊的 `batch.mjs`、`panes.mjs` 等是直接打 `BASE` 指的伺服器，伺服器要登入時會失敗（用開發版、不設帳密的伺服器跑）。

  `FAKE_EMPTY_FIRST`（回空的原句）、`FAKE_EXAM_BAD_FIRST`（出題第一次回不合格的題）。測試分析時設 `ANALYZE_GROUP=1` 可固定成逐句呼叫。

SSE 事件：`meta`（總句數）→ `sentence`（單句結果，附 `cached`）→ `progress` → `done`。
快取命中的句子會在毫秒內先推出，其餘才送去分析。

分析途中後端每 8 秒送一次心跳（`: ping`）。瀏覽器的 fetch 串流在後端消失時不一定會結束
（實測砍掉後端後 `read()` 會一直懸著，`AbortController` 也打不斷已開始讀取的 body），
所以前端讓每次讀取跟 30 秒逾時賽跑：有心跳就代表後端還在，30 秒無聲才判定中斷。
中斷時未完成的句子會標示出來並提供「重新分析」—— 已完成的句子都在快取裡，不會重跑。

環境變數：`PORT`(8787)、`HOST`(127.0.0.1)、`AUTH_USER` / `AUTH_PASS`(無，老師帳密)、`STUDENT_USER` / `STUDENT_PASS`(無，學生帳密，選填)、`STUDENT_OCR_PER_DAY`(10，學生每天免審辨識幾張)、`AUTH_TOKEN`(無，舊的存取碼)、`SESSION_DAYS`(90)、`ANALYZE_GROUP`(6，每批幾句；1 = 逐句)、`EXAM_MODEL`(sonnet)、`PAPER_DAYS`(30)、`PAPER_KEEP`(20)、`QUESTION_MAX`(500)、`MAX_CHARS`(4000)、
`MAX_SENTENCES`(25)、`MAX_ARTICLE_CHARS`(20000)、`MAX_ARTICLE_SENTENCES`(120)、`CONCURRENCY`(6)、`ANALYZER_MODEL`(opus)、`HISTORY_DAYS`(30)、`DB_FILE`(data/cache.db)。

### 額度與對外開放

分析由本機 `claude` CLI 執行，**額度計入執行這台機器上登入的 Claude 帳號**。
程式碼不含任何憑證，別人 clone 後要自己 `claude login`，花的是他們自己的額度。

因此伺服器預設**只監聽 127.0.0.1**。要讓區網其他裝置連線：

```bash
HOST=0.0.0.0 AUTH_USER=帳號 AUTH_PASS=密碼 npm start
```

打開網頁會先看到登入框（見上面的「登入」）。舊的 `AUTH_TOKEN` 仍可用於腳本。
沒設任何驗證就對外開放時，啟動訊息會警告 —— 任何連得到的人都能無限消耗你的額度。

## 用量與歷史

每次分析完成後，畫面上會顯示這次用掉的 token 與參考費用：

```
句數 3   耗時 13.6s   輸入 90,806 tokens   輸出 3,090 tokens   參考費用 $0.306
```

參考費用是依 Claude API 牌價換算的估算值。實際分析走本機 Claude 訂閱，
**不會另外收費，但會消耗訂閱額度** —— 這個數字是用來掌握用量規模的。
全部命中快取時不會呼叫模型，也就不產生任何用量。

交卷後**答錯的題目會排到最前面**（兩個分頁都是），答對的收在分隔線後面 ——
要訂正的東西不該埋在一堆答對的裡面。題號維持原本的順序，
那是當下那份測驗的題號。

接著可以按「訂正錯題」，**把答錯的原題重出一次**。
訂正**不列入正確率，也不會把那個字移出待加強** ——
答案剛才已經看過了，再答對一次不代表背起來了。
更重要的是：若計入，Leitner 的盒子會從 0 被推回 1，
那個字反而更晚才再出現，等於答錯讓它變得更少考，整個反了。
訂正的作答仍會寫進資料庫（`is_fix = 1`），只是所有統計與排程都排除。

題型、單字、例句一律不換 —— 訂正就是把原本那題做對，
拼錯 interesting 的人要再拼一次 interesting，換成聽考測的是別的東西。
只有選擇題的選項順序會打散，避免靠記得剛才的位置作答。
單字與句型練習兩個分頁都有。

出好的題目（含答案）存在 SQLite，不放記憶體 —— 伺服器重啟時，
作答到一半的人才不會按交卷就看到「這份測驗已失效」。一週後自動清掉。

「歷史」分頁有今天／本月／全部的累計用量，以及過去的紀錄。
**每一個會花額度的操作都會記錄**，列表上標示類型：

| 類型 | 什麼時候 |
|---|---|
| 分析句子 | 「句子」分頁按「分析」、單字表的批次分析例句（後台） |
| 照片抄句子 | 在「句子」或「文章」拍照／拖曳／貼上課本照片 |
| 照片抄單字 | 在「單字」拍照建立字表 |
| 建立字表 | 貼上或加進既有字表時整理詞性、例句、音節 |
| 測驗卷出題（模型） | 請模型出閱讀題、語意干擾項、情境應答、延伸題（入庫的題數與花費） |
| 測驗卷 AI 批改 | 一次批改全部造句與翻譯 |

分析那條在逐句跑完之後才記錄，所以中途遇到額度用盡而停下來，
已經花掉的部分仍然看得到。程式出題、批改、統計、朗讀都不呼叫模型，不會出現在這裡；測驗卷請模型出題與 AI 批改會記錄花費（點了沒有原文可看）。
分析句子那筆點了會載回原文重新顯示；建立字表那筆點了會直接切到**那一份**字表。
字表若已被刪除，紀錄會標示「已刪除」並說明用量仍然保留 —— 刪字表不該讓帳消失。
點任一筆會載回原文重新顯示 —— 因為全部命中快取，所以是 0 秒且免費。

歷史**原文**保留 `HISTORY_DAYS`（預設 30）天後自動清除，啟動時與每 6 小時各清一次。
分析快取本身不受影響，那是可以重複利用的資產。

### 訂閱額度

Claude CLI **沒有提供查詢剩餘訂閱額度的介面** —— 沒有 `usage` 子指令，
`--output-format json` 的回傳欄位裡也沒有 rate limit / quota，`claude auth status`
只給方案類型不給用量。資料本身存在（Claude app 的 Settings → Usage 就在顯示），
只是 CLI 沒開這個口。

所以本工具**只顯示自己的用量**（token 與 API 牌價換算的參考費用），
不假裝知道你還剩多少額度。真實額度請看 **Claude app → Settings → Usage**，
那裡是 5 小時 session 與每週兩種視窗的實際百分比。

額度真的用盡時，CLI 會回報 rate limit，伺服器會**立即中止**其餘句子的分析
（這類錯誤重試沒有意義），畫面顯示「訂閱額度似乎已用盡」，已完成的句子仍保留在快取。
認證失效也會比照處理並提示重新 `claude` 登入。

## 快取與搬遷

快取落在本機單一檔案 `data/cache.db`（SQLite），存的是**你貼過的每一句原文與完整分析**。
`data/` 已在 `.gitignore` 內，不會進版控。

要讓快取跟著走，用 JSONL 匯出而不是直接複製 `.db` —— JSONL 可以進版控、可 diff、可合併：

```bash
npm run cache:seed                      # 匯出到 fixtures/seed-cache.jsonl（這個檔進版控）
npm start                               # 新機器首次啟動會自動載入種子
```

其他指令：

```bash
npm run cache -- export out.jsonl --since 2026-01-01   # 增量匯出
npm run cache -- import out.jsonl                      # 匯入（預設保留本機既有，只合併命中次數）
npm run cache -- import out.jsonl --force              # 覆蓋同一句的既有結果
npm run cache -- prune 90                              # 刪除超過 90 天的紀錄
npm run cache:info                                     # 狀態；同時 checkpoint WAL
```

合併語意：同一句（hash 相同）預設**不覆蓋**本機版本，只把命中次數加總，所以兩台機器各自累積後互相匯入不會打架。

若真的要直接複製 `data/cache.db`，先跑 `npm run cache:info` 把 WAL 折回主檔，否則會漏掉最近的寫入。
