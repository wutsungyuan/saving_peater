## 手機

伺服器送出 `prototype/index.html` 時會補上 doctype、charset 與 viewport ——
那份檔案是給 Artifact 用的格式（發布時平台自動包骨架），我們自己送就得補，
否則手機上會是 quirks 模式加 980px 的版面寬度，整頁縮小到看不清楚。
骨架放在 `serveStatic()` 而不是寫進檔案，是為了不破壞 Artifact 的發布規則。

圖例（句子成分、詞性、代名詞格位）在手機上收到左右邊緣，
從邊緣往內滑可以拉出來，邊緣也有把手可以點 ——
純手勢沒有任何提示，第一次用的人不會知道。
抽屜內容直接取自側欄，不另外維護一份。

手機版（≤560px）另外做了：分頁改為可橫向捲且字不折行、開頭說明收成兩行可展開、
句子與標註字級縮小、按鈕與選項高度拉到 40px 以上、輸入框字級固定 16px
（iOS 低於 16px 會自動放大整頁）、出題後自動捲到第一題。

用無頭 Chrome 量過 360／390／430px 五個分頁都沒有橫向溢出，
768／1180／1400px 的桌機版面不受影響。

# 英文句型解剖

貼上一句話或一段英文文章，逐句分析**句型、詞性、時態、文法問題**，並給繁體中文翻譯。
文法規則取自 `國中英文文法_句型與時態.md`（五大基本句型 ＋ 16 種時態）。

## 快速開始

```bash
npm start          # http://127.0.0.1:8787
```

零依賴 —— 只用 Node 22 內建的 `node:http` 與 `node:sqlite`。
分析透過 Claude Code headless（`claude -p`）呼叫，使用你現有的 Claude 訂閱認證，不需要 API key。

## 它會分析什麼

| 層次 | 內容 |
| --- | --- |
| 句型 | 五大基本句型（S+V ／ S+V+C ／ S+V+O ／ S+V+IO+DO ／ S+V+O+C），逐成分標出 S/V/O/C/IO/DO 與修飾語 |
| 詞性 | 12 種（n, pron, v, aux, adj, adv, prep, conj, art, num, to, interj），形容詞與副詞特別標色 |
| 代名詞格位 | 主格／受格／所有格／所有格代名詞／反身，`her`、`his` 這類一字多格也能分辨 |
| 時態 | 4 時間 × 4 狀態共 16 格，標示是否屬於國中範圍的 7 種 |
| 動詞 | 三態（原形／過去式／過去分詞）＋ -ing ＋ 三單，不規則動詞標 `v°` |
| 文法 | 12 類常見錯誤偵測（連結動詞接副詞、第三人稱單數、完成式配過去時間、to/for、受格…） |
| 語序 | 「主、動、賓、方、地、時」六格拆解 |
| 翻譯 | 繁體中文（台灣用語） |

### 國中範圍的判定

範圍是依**課綱**而非講義的涵蓋範圍 —— 講義只教五大句型與時態，
但被動語態、比較級、關係子句這些國中也要學。

**算在範圍內**：疑問句（Yes/No、Wh-、附加問句）、間接問句、否定句、被動語態、
比較級與最高級、祈使句、There be、使役與感官動詞、不定詞與動名詞、
關係子句的基礎用法（who / which / that）、so…that、too…to，
以及 7 種時態（必學 6 種＋過去完成式）。

**標為超出範圍**：分詞構句、假設語氣、完成進行式、未來進行式與未來完成式、
過去未來式、關係子句的進階用法（whose、介系詞 + 關代、非限定）、
that 引導的名詞子句、倒裝句。超綱時仍會照實分析主幹，只是多一個標示與說明。

被動語態的句型依**轉換後剩什麼**決定：主動句型三 → 被動句型一、
主動句型四 → 被動句型三、主動句型五 → 被動句型二，並附主動語態的改寫。
非英文、不完整片語、無意義字串會標 `issue` 並明說無法分析，不會硬掰。

## 單字表

字表有三種建立方式：**貼上文字**（一行一個，可用逗號接中文）、
**拍照／選檔**，或把圖片**直接拖進來／按 ⌘V 貼上** ——
從 LINE、相簿、Finder 拖過來都可以，整個「單字」分頁都是放置區，
表單沒開會自動打開。

拍照辨識會把課本單字表抄成文字填進輸入框，**讓你核對後再建立** ——
辨識可能有誤，不直接拿去花額度充實。實測一張課本頁 10 秒抄出 25 個字，
而且會自動忽略手寫筆記、音標、詞性方格與發音要點。
照片上傳前先在瀏覽器縮到最長邊 1600px，手機原圖約縮到十分之一。
照片只在辨識當下寫成暫存檔，用完立刻刪除，不留在硬碟上。

字表可以**多選** —— 按「多選」後點字表就是加入／移除，單字清單、
測驗與批次分析都會把選取的字表合在一起。至少要留一份。
刪除會連同那些字表的**所有作答與熟練度一起消失**（句子分析快取不受影響，
那是以句子為單位、和字表無關），所以要按兩次確認。

字表名稱預設是當天日期（`10/7 單字`），同一天建第二份會自動加序號；
想改名直接覆蓋即可。

每個例句後面有「分析」，點了跳到句型分析。按鈕會分成兩種狀態：
**虛線框**＝還沒分析（點了會花一次額度）、**實線框加勾**＝已分析過
（點了瞬間出結果，不花額度）。不只靠顏色區分，色盲或黑白列印也看得出差別。
分析完回到清單會立刻更新。字表上方的「批次分析例句」
會把所有例句一次分析完，之後點任何一句都是瞬間且不花額度的。

### 為什麼批次比較省

每次呼叫模型都要重讀約 34K tokens 的系統提示，逐句送就是付 N 次。實測六句：

| | 呼叫次數 | 費用 | 輸出 tokens | 時間 |
|---|---|---|---|---|
| 逐句 | 6 | $0.164 | 6,125 | 72s |
| 整批 | 1 | $0.099 | 4,592 | 37s |

省 40% 費用、49% 時間，而句型、時態、詞性對齊與原句都與逐句分析完全一致。
`analyzeMany()` 每 8 句併一次呼叫，回來後用 `original` 逐一對回去，
模型漏句或併句時那幾句自動單獨重送 —— 寧可多花也不能給錯的結果。

例句分析完會併入練習題庫（一份字表約多 26 句），出題不另外花錢。

呼叫模型的兩個步驟（辨識、建立）都會在輸入框上蓋一個轉圈指示並跳秒數 ——
整理一份字表要將近一分鐘，沒有東西在動會讓人以為當掉了。

「單字」分頁底下分成「單字清單」與「單字測驗」兩個子頁，
**預設停在單字清單** —— 平常是背單字、看例句，要考試才切過去。

「單字」分頁貼上老師給的考試範圍（一行一個，可用逗號接中文），系統會整理出
**每個詞性的意思、例句、音節拆解、拼字提醒、易混淆字與衍生字**，然後循環測驗。

建立時每批單字呼叫一次模型（15 個字約一分鐘），**之後所有測驗都由程式生成，不再花額度**。

### 五種測驗模式

| 模式 | 形式 |
| --- | --- |
| 中考英 | 看中文寫英文，提示給音節骨架 `__-___-__-___` |
| 英考中 | 看英文選中文，誘答從同字表其他字取 |
| 聽考 | 用朗讀唸出單字，聽完拼出來（配合自然拼音） |
| 例句填空 | 例句挖空填入，變化形（finishes）與原形都接受 |
| 詞義辨析 | 同一個字在不同句子裡是不同意思，選出這句是哪個 |

最後一種是為「一詞多義」設計的。實測 15 個字裡有 9 個是多詞性，
例如 `free` 有免費的／自由的／有空的三個意思、`own` 有形容詞「自己的」與動詞「擁有」，
每個意思都配一個能看出語境的例句。

題型用輪流取的方式，五種各佔 20%。

### 間隔複習（Leitner）

每個字有一個「盒子」：答對往上一盒、答錯打回第一盒。盒子越高，下次出現的間隔越長
（10 分鐘 → 1 小時 → 1 天 → 3 天 → 7 天 → 14 天）。出題時到期的字優先，
沒考過的次之，已經熟的最後。這樣循環練下去，弱的字自然會一直回來。

單字清單裡每個單字與每個例句旁邊都有朗讀鈕，再按一次停止。

### 不輸出音標

孩子學的是自然拼音，所以提供**音節拆解**（`un-der-wa-ter`）與**拼字提醒**
（lesson 中間兩個 s、design 的 g 不發音），不輸出 KK 音標。發音靠朗讀功能直接聽。

## 練習模式

介面上方切到「句子練習」，從**你分析過的句子**反向生成題目。五種題型：

| 題型 | 形式 | 範例 |
| --- | --- | --- |
| 句型判斷 | 五選一 | `Last week our teacher gave us a difficult test.` → 句型四 |
| 時態填空 | 填空（給原形） | `The news ______ his parents proud.`（make）→ made |
| 詞性判斷 | 四選一 | 「confident」在這句是什麼詞性？→ adj |
| 動詞三態 | 兩格填空 | `give → ______ → ______` → gave, given |
| 改錯 | 填空 | `The soup tastes well.` → tastes good |
| 代名詞格位 | 五選一 | 「mine」在這句是哪一種格位？→ 所有格代名詞 |
| 代名詞填空 | 填空（給主格） | `She is ______ teacher.`（I）→ my |

代名詞填空只出「提示的主格 ≠ 答案」的題目 —— (I) → I 等於直接給答案，沒有練習價值。

**出題不呼叫模型。** 分析結果裡已有句型、成分、時態關鍵字、詞性、三態與錯誤修正，
由程式反向生成，所以零成本、1 毫秒完成，而且題目與解答必然和分析一致。

解答沿用講義的解說語言（等號測試、關鍵字 → 時態、三態表）。
答案不隨題目下發，交卷時才由後端批改並記錄，批改時大小寫、空白、句尾標點都不計較。

## 朗讀

每句卡片右上角有朗讀按鈕，點下去唸該句，**唸到哪個字那個字就亮起來** ——
底下的句型色線與詞性標示仍然看得見，聽到 `made` 的同時看得到它被標成 `v°`。
工具列可選語音與速度（慢 0.6／適中 0.85／正常 1.0），設定存在 localStorage。

**完全不消耗任何 API 額度**，也不需要網路 —— 用的是瀏覽器內建的 Web Speech API。

### 發聲層是可抽換模組

`prototype/speech.js` 是獨立的一支，介面固定：

```js
Speech.ready()                  // 等語音清單載入（Chrome 是非同步的）
Speech.available()              // 這個瀏覽器能不能發聲
Speech.voices()                 // [{ id, name, lang, local, wordEvents }]
Speech.settings / setSettings({ voiceId, rate })
Speech.speak(text, { onWord, onStart, onEnd, onError })
Speech.stop() / Speech.speaking()
```

### 代名詞格位是程式決定的

`mine / yours / hers / my / me / I` 這些形式只有一種可能，所以**由程式直接判定**，
不交給模型碰運氣（實測模型偶爾會漏填）。只有 `her`（受格或所有格）、
`his`（所有格或所有格代名詞）、`its`、`it`、`you` 真有歧義時才採用模型的判斷，
模型沒填時再用「後面有沒有接名詞」的規則補上。

這個校正在**讀取快取時也會執行**，所以規則更新後舊的分析結果不必重跑就會補上格位。

`onWord({ start, end })` 的字元座標與分析結果的 `words[].start/end` 同一套，
所以逐字標示不需要額外對齊。之後要換成 Kokoro-82M 等本機神經網路 TTS，
只要替換這一支並維持同樣介面，呼叫端完全不用動。

### 跨平台的語音選擇

不寫死語音名稱（`Samantha` 在 Windows 不存在）。選擇順序：

1. **只挑本機語音** —— 實測雲端語音（Google US English）**完全不發逐字事件**，
   選到就會失去逐字標示
2. 依偏好清單：macOS 的 Samantha / Alex / Daniel…、Windows 的 Microsoft Zira / David / Mark…
3. 過濾掉 macOS 的趣味語音（Bells、Boing、Zarvox…）
4. 都沒有就取第一個英語本機語音

選單裡不支援逐字的語音會標示「（無逐字標示）」。

## 弱點統計

「弱點」分頁統計各維度的正確率，依**五大句型、必學 6 時態、詞性、題型**四組呈現：

- 橫向長條依正確率著色（紅＝最弱、琥珀＝待加強、綠＝熟練），
  百分比、分數與狀態文字一律並列，**不靠顏色辨識**
- 作答數少於 2 的維度標為「資料不足」，不下判斷
- 沒作答過的句型與時態仍然列出並標「無資料」，才看得出哪些還沒練到
- 超出國中範圍的時態（現在完成進行式等）另外列在時態區下方

色票經 `dataviz` 技能的 `validate_palette.js` 驗證：
紅 `#a82a1e` / 琥珀 `#b8821f` / 綠 `#0f6637`，
色盲下相鄰 ΔE 15.1、正常視覺 20.1、對比皆 ≥3:1，全數通過。

### 弱點驅動出題

出題時依這些正確率加權，權重 `0.25 + (1 − 正確率) × 2.25` ——
全錯的維度約 2.5 倍、全對的約 0.25 倍、沒作答過的為中性 1 倍。

實測 200 輪、每輪 10 題的分佈變化：

| 維度 | 正確率 | 關閉加權 | 開啟加權 |
| --- | --- | --- | --- |
| 句型四 | 0% | 13.5% | **25.8%** |
| 句型一 | 25% | 20.0% | **34.5%** |
| 句型三 | 83% | 41.8% | 22.3% |
| 過去簡單式 | 20% | 52.8% | **65.5%** |
| 現在簡單式 | 80% | 38.5% | 24.0% |

使用者代碼存在瀏覽器的 localStorage，不需登入；換瀏覽器就是新的統計。

## API

| 端點 | 說明 |
| --- | --- |
| `GET /api/health` | 回報模型與上限 |
| `POST /api/analyze` | `{"text":"..."}` → SSE 串流，每分析完一句推一句 |
| `POST /api/exercises` | `{"count":10,"types":[...]}` → 題目（不含答案） |
| `POST /api/attempts` | `{"quizId","userToken","answers"}` → 批改結果並記錄 |
| `GET /api/weakness?user=` | 弱點統計：依題型／句型／時態／詞性的正確率 |
| `POST /api/wordset-ocr` | 課本照片 → 單字清單文字（會呼叫模型） |
| `GET/POST/DELETE /api/wordsets` | 字表的列出、建立（會呼叫模型充實）與刪除 |
| `GET /api/wordset?id=&user=` | 一份字表的單字與進度 |
| `POST /api/wordquiz` | 依 Leitner 排程出單字測驗 |
| `POST /api/wordattempts` | 批改並更新盒子與到期時間 |
| `POST /api/exercises` 的 `userToken` | 帶入後出題會依該使用者的弱點加權；`focusWeak:false` 可關閉 |
| `GET /api/history` | 用量累計與分析紀錄；帶 `?id=` 取回該筆原文 |
| `GET /api/stats` | 快取統計與句型／時態分佈 |

SSE 事件：`meta`（總句數）→ `sentence`（單句結果，附 `cached`）→ `progress` → `done`。
快取命中的句子會在毫秒內先推出，其餘才送去分析。

分析途中後端每 8 秒送一次心跳（`: ping`）。瀏覽器的 fetch 串流在後端消失時不一定會結束
（實測砍掉後端後 `read()` 會一直懸著，`AbortController` 也打不斷已開始讀取的 body），
所以前端讓每次讀取跟 30 秒逾時賽跑：有心跳就代表後端還在，30 秒無聲才判定中斷。
中斷時未完成的句子會標示出來並提供「重新分析」—— 已完成的句子都在快取裡，不會重跑。

環境變數：`PORT`(8787)、`HOST`(127.0.0.1)、`AUTH_TOKEN`(無)、`MAX_CHARS`(4000)、
`MAX_SENTENCES`(25)、`CONCURRENCY`(6)、`ANALYZER_MODEL`(opus)、`HISTORY_DAYS`(30)。

### 額度與對外開放

分析由本機 `claude` CLI 執行，**額度計入執行這台機器上登入的 Claude 帳號**。
程式碼不含任何憑證，別人 clone 後要自己 `claude login`，花的是他們自己的額度。

因此伺服器預設**只監聽 127.0.0.1**。要讓區網其他裝置連線：

```bash
HOST=0.0.0.0 AUTH_TOKEN=你自訂的字串 npm start
```

分享網址時帶上 `?token=你自訂的字串`，前端會記住。
未設 `AUTH_TOKEN` 就對外開放時，啟動訊息會警告 —— 任何連得到的人都能無限消耗你的額度。

## 用量與歷史

每次分析完成後，畫面上會顯示這次用掉的 token 與參考費用：

```
句數 3   耗時 13.6s   輸入 90,806 tokens   輸出 3,090 tokens   參考費用 $0.306
```

參考費用是依 Claude API 牌價換算的估算值。實際分析走本機 Claude 訂閱，
**不會另外收費，但會消耗訂閱額度** —— 這個數字是用來掌握用量規模的。
全部命中快取時不會呼叫模型，也就不產生任何用量。

交卷後**答錯的題目會排到最前面**，答對的收在分隔線後面 ——
要訂正的東西不該埋在一堆答對的裡面。題號維持原本的順序，
那是當下那份測驗的題號。

接著可以按「訂正錯題」，**把答錯的原題重出一次**。
訂正**不列入正確率，也不會把那個字移出待加強** ——
答案剛才已經看過了，再答對一次不代表背起來了。
更重要的是：若計入，Leitner 的盒子會從 0 被推回 1，
那個字反而更晚才再出現，等於答錯讓它變得更少考，整個反了。
訂正的作答仍會寫進資料庫（`is_fix = 1`），只是所有統計與排程都排除。

題型、單字、例句一律不換 —— 訂正就是把原本那題做對，
拼錯 interesting 的人要再拼一次 interesting，換成聽考測的是別的東西。
只有選擇題的選項順序會打散，避免靠記得剛才的位置作答。
單字與句型練習兩個分頁都有。

出好的題目（含答案）存在 SQLite，不放記憶體 —— 伺服器重啟時，
作答到一半的人才不會按交卷就看到「這份測驗已失效」。一週後自動清掉。

「歷史」分頁有今天／本月／全部的累計用量，以及過去的紀錄。
**三種會呼叫模型的操作都會記錄**：分析句子、照片辨識、建立字表，列表上各自標示類型。
分析句子那筆點了會載回原文重新顯示；建立字表那筆點了會直接切到**那一份**字表。
字表若已被刪除，紀錄會標示「已刪除」並說明用量仍然保留 —— 刪字表不該讓帳消失。
點任一筆會載回原文重新顯示 —— 因為全部命中快取，所以是 0 秒且免費。

歷史**原文**保留 `HISTORY_DAYS`（預設 30）天後自動清除，啟動時與每 6 小時各清一次。
分析快取本身不受影響，那是可以重複利用的資產。

### 訂閱額度

Claude CLI **沒有提供查詢剩餘訂閱額度的介面** —— 沒有 `usage` 子指令，
`--output-format json` 的回傳欄位裡也沒有 rate limit / quota，`claude auth status`
只給方案類型不給用量。資料本身存在（Claude app 的 Settings → Usage 就在顯示），
只是 CLI 沒開這個口。

所以本工具**只顯示自己的用量**（token 與 API 牌價換算的參考費用），
不假裝知道你還剩多少額度。真實額度請看 **Claude app → Settings → Usage**，
那裡是 5 小時 session 與每週兩種視窗的實際百分比。

額度真的用盡時，CLI 會回報 rate limit，伺服器會**立即中止**其餘句子的分析
（這類錯誤重試沒有意義），畫面顯示「訂閱額度似乎已用盡」，已完成的句子仍保留在快取。
認證失效也會比照處理並提示重新 `claude` 登入。

## 快取與搬遷

快取落在本機單一檔案 `data/cache.db`（SQLite），存的是**你貼過的每一句原文與完整分析**。
`data/` 已在 `.gitignore` 內，不會進版控。

要讓快取跟著走，用 JSONL 匯出而不是直接複製 `.db` —— JSONL 可以進版控、可 diff、可合併：

```bash
npm run cache:seed                      # 匯出到 fixtures/seed-cache.jsonl（這個檔進版控）
npm start                               # 新機器首次啟動會自動載入種子
```

其他指令：

```bash
npm run cache -- export out.jsonl --since 2026-01-01   # 增量匯出
npm run cache -- import out.jsonl                      # 匯入（預設保留本機既有，只合併命中次數）
npm run cache -- import out.jsonl --force              # 覆蓋同一句的既有結果
npm run cache -- prune 90                              # 刪除超過 90 天的紀錄
npm run cache:info                                     # 狀態；同時 checkpoint WAL
```

合併語意：同一句（hash 相同）預設**不覆蓋**本機版本，只把命中次數加總，所以兩台機器各自累積後互相匯入不會打架。

若真的要直接複製 `data/cache.db`，先跑 `npm run cache:info` 把 WAL 折回主檔，否則會漏掉最近的寫入。
